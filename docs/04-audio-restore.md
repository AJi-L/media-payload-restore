# 04 · 音频负载还原

视频修好之后，音频往往还有一层小改写。现象：

```
[aac] Prediction is not allowed in AAC-LC.
[aac] Input buffer exhausted before END element found
[aac] Error submitting packet to decoder
```

## 形态

容器的采样表（`stsz`/`stsc`/`stco`）本身是**完全正确**的，样本长度也对，
问题出在样本内容上：

- **每 256 个样本**，第一个样本里会先塞一个 17 字节的标记块，内容形如

  ```
  de 02 00  +  "Lavc58.59.102"  +  00
  ```

  （中间那串 ASCII 是编码器的版本字符串，属于无害噪声）

- **紧随标记块之后的那一帧，被整体位移了 1 位**

## 还原

```python
# 样本 = [17 字节标记块][被位移 1 位的帧]
frame = payload_after_marker >> 1        # 右移 1 位（最高位由前一字节最低位补入）
```

注意这里的"右移"是**逐字节带进位**的：

```python
out[i] = (b[i] >> 1) | ((b[i-1] & 1) << 7)     # 第 0 字节的前驱取 0
```

验证方法很直观：**标记帧还原之后，应当与相邻帧逐字节一致**（同一段静音/静止画面时）。
对不上就说明位移方向或进位方向错了（左移、右移都试一下，只会有一种对）。

## 处理不了的少数帧

约有百分之几的标记帧，其内容在发行方侧就已丢失 —— 表现是：

- 各种位移方向都解不出合法 AAC；
- 解码器报错；
- 这些帧本来都是 `global_gain = 0xFF` 的**静音帧**。

处理方式：用同一码流里的一个**正常静音帧**替换掉它们。
这样解码器不再报错，听感上也没有任何损失（本来就没有内容）。
替换数量会打印出来，例如：

```
音频: 64272 个样本, 252 个标记块 (还原 227, 以静音帧替代 25)
```

## 关于 `esds` / AudioSpecificConfig

有些文件的 `esds` 里的 ASC 是无效值（例如解出来 `audioObjectType` 明显越界）。
**不用去修它**：直接按裸 AAC-LC / 44100 / 立体声重建 ADTS 头即可，
真正的参数由码流本身决定（元素类型 CPE 就是立体声）。

```python
def adts(payload, ch=2):
    fl = len(payload) + 7
    return bytes([0xFF, 0xF1, 0x40 | (4 << 2) | ((ch >> 2) & 1),
                  ((ch & 3) << 6) | ((fl >> 11) & 3), (fl >> 3) & 0xFF,
                  ((fl & 7) << 5) | 0x1F, 0xFC]) + payload
```

## 校验

逐个标记块做一次"迷你解码测试"是最靠谱的判定方式：把候选帧连同前后各一帧
拼成一个小 ADTS 文件，丢给 `ffmpeg -f aac` 解一遍，看有没有报错。
脚本 `src/payload_restore.py` 里就是这么做的（`_decode_ok()`），
只有通过测试的帧才保留，其余用静音帧替换。

> 注意给 `ffmpeg` 加 `-nostdin` 并把 `stdin` 指向 `DEVNULL`，否则在无人值守的
> 批处理里它可能卡住等待输入。
